Selection Diagnostics now refreshes automatically as the selection, document, completed edit or connection changes.

Rapid changes share a deferred read. Closing and reopening the window cleans up its subscriptions. Manual Read remains available, and automatic notification failures retain manual diagnostics.

Captures do not reenter during nested UI work and are discarded if the document or report window changes. The existing developer-only visibility, 256-entry report limit and explicit Debug Move action remain.

Selected graphics now report the labels of their underlying design objects, including updated component names after a rename.

Designer 10.5.0 and 10.5.1 with Mods Core 0.1.11 passed bounded checks for selection labels,
rapid selection changes, rename/position edits and Undo/Redo, manual Read,
document replacement, Emulate mode reporting and one diagnostics-window
close/reopen cycle. That cycle was not a full application restart.

The 10.5.1 F7 comparison reproduced a dirty document and unavailable Undo/Redo
both with and without product mods. Both saved results added settings files and
cached control values while the checked component fields stayed unchanged.
This is consistent with Designer synchronizing settings when leaving Emulate;
Schematic Tools does not clear that state. The comparison used profile-isolation
instrumentation and does not establish complete document or binary-snapshot
equivalence. Automatic refresh has no fixed latency or one-report-per-action
guarantee.

Native unsupported-selection/getter-failure recovery, pending-callback shutdown
races, application cold reopen, and live Core/hardware acceptance
remain untested. Exact-build opt-in does not establish compatibility.
